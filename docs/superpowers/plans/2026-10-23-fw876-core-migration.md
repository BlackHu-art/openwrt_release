> 执行方式：并行处理独立模块，测试先行；整体验证和独立复核后交付。

**目标：** 将 SSR 与京东云固件实际使用、且 fw876 提供的配套核心统一到 `fw876/helloworld@v198.2`，保留官方 Passwall2 并适配共享核心。

**已确认设计：** 用户要求移除现有启动和 DNS 修复；不改变其他插件选择。以 `origin/master@8c9a84c` 为基线，源码固定到 `45893d778767f3bdb2fcb6e873cf8f9a667d94d4`。原方案保留旧修复已被本次指令替代。

**架构：** 受管源码记录原始 fw876 配方、完整补丁及文件哈希；生产准备仅应用明确的新版本集成调整。共享核心运行时更新归 fw876 组件更新器管理，Passwall2 的官方 Xray 覆盖入口关闭并说明管理入口。sing-box、OpenClash 和其他非 fw876 核心维持现状。

**技术：** OpenWrt Make/Kconfig、Bash、Lua、Python unittest、Windows Git Bash、Linux CI。

## 全局约束

- 其他 LuCI 插件、设备及目标配置不变。SSR 自身依赖选项显式保持已有能力，新增必需依赖单独记录。
- 不把未选择的 fw876 可选核心加入固件；UPX 为所选 Xray 的构建依赖。
- 不继续生产调用 190 系列启动锁、DNS 事务运行脚本。历史测试如保留，明确隔离为历史回归，不能充当新实现验证。
- 保留源码防漂移、版本门槛、包/rootfs 完整性检查；不能通过取消校验完成迁移。
- 所有 fw876 同名配方只保留一个生产来源，禁止后续在线覆盖 tcping、MosDNS 或 Xray。
- 不改动路由器。用户后续已明确要求：验证通过后提交推送，并触发 `jdcloud_ipq60xx_immwrt` 编译；沿用既有 `Release WRT` 工作流和默认配置片段。

## 审查重点

- Passwall2 的更新、配置路径覆盖是否仍能换回官方 Xray。
- v198.2 默认值是否悄悄删除现有核心或加入额外可选核心。
- 原始源码、准备后源码、安装文件权限、成品清单是否一致且准备幂等。
- 测试是否真正使用新 SSR 生成器；官方 Xray 通过不得冒充 fw 定制核心通过。
- IPv6/防火墙/DNS 用例仅验证上游现有行为，不重新引入用户拒绝的启动/DNS修复。
